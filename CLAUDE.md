# Heplio

Unofficial INSPIRE-HEP (high-energy physics literature database) client for
iOS/iPadOS, built entirely in Swift Playgrounds as a `.swiftpm` App Project.

## Environment constraints

- Swift Playgrounds only — no Xcode. No Objective-C, no macOS/watchOS/tvOS
  targets, no Info.plist editing, no multi-target/multi-local-package
  splitting. `Package.swift` is auto-generated by Playgrounds; treat it as
  generated output, not hand-authored config.
- Single target (`AppModule`), organized purely by folder under
  `Sources/HeplioApp/`: `Models/`, `Networking/`, `Persistence/`, `Views/`
  (feature-named subfolders, e.g. `Search/`, `Home/`, `Detail/`,
  `Settings/`, `History/`, plus `Shared/` for views used by more than one
  feature), `Recommendation/`, `Extensions/`, `Utilities/`.
- Can't be built or run on Linux (`AppleProductTypes`/iOS-only APIs).
  `Foundation`-only code (models, networking) can be compiled and exercised
  standalone on Linux — see [Testing approach](Docs/testing.md). Anything
  importing `SwiftUI` needs verification in Swift Playgrounds on-device.
- Syncthing syncs this directory. It can drop `*.sync-conflict-*.swift`
  files into `Sources/`, which get compiled and cause "invalid
  redeclaration" / "ambiguous type lookup" errors. If the build reports
  those, look for and remove stray `.sync-conflict-*` files first.
- All user-facing strings are English.

## Architecture notes

**Use native SwiftUI components and system-provided styling exclusively —
do not invent bespoke design elements.** Reach for what Apple's own apps
(Music, News, Mail, Notes, Settings) do with stock SwiftUI. The docs
below are the deep dive per area — each records the *why*, including the
device-only bugs and rejected approaches behind non-obvious choices, so
they don't get re-discovered or re-broken. Read the relevant one before
touching that area:

- [UI philosophy](Docs/ui-philosophy.md) — the "standard components
  only" rule, the narrow exceptions to it (math typesetting, figure
  carousel, card chrome), the App-Store-style zoom transition, and two
  known, accepted Swift Playgrounds/iOS 26 rendering limitations that
  aren't worth re-attempting.
- [Networking and data flow](Docs/networking.md) — the four-layer
  pipeline (`InspireHEPClient` → `InspireRecord` → `PaperService` →
  `ResponseCache`), `PaperPager`, `LoadState`, and how rate-limit errors
  are told apart from network failures.
- [Sorting](Docs/sorting.md) — the shared sort control and why
  `relevance` has to mean "send no `sort` parameter".
- [Author pages](Docs/author-pages.md) — author lookup as a plain
  query, and the navigation-destination rules that keep author pushes
  well-behaved.
- [Library, history, and search history](Docs/library-and-history.md) —
  the three SwiftData models, why queryable fields are duplicated out of
  the JSON snapshot, and the iCloud-sync design constraints new models
  must follow.
- [Explore](Docs/explore.md) — the static, algorithm-free browsable
  catalog and its hard-coded shelf list.
- [New](Docs/new.md) — the time-ordered front page, including three
  container choices (`List`, flat rows, `Rectangle` rules) that are scar
  tissue from real on-device bugs — don't revert them without reading why.
- [Home, and the recommendation function](Docs/home-and-recommendation.md)
  — the ranking function (`Recommender`), why nothing it computes is
  ever stored, and the day-rotating shelf stream built on top of it.
- [Testing approach](Docs/testing.md) — how model/networking/HTML-
  generating changes get verified from this Linux dev machine against
  the real INSPIRE API.
- [INSPIRE query syntax](Docs/query-syntax.md) — the `q=` query
  vocabulary Explore, New, and the recommendation layer are all built on.

## Milestones

- [x] M0: Project skeleton (tab structure, empty views)
- [x] M1: Data model (`Paper: Codable`) + `InspireHEPClient`
- [x] M2: Search tab (`.searchable()`, result rows, list→detail navigation)
- [x] M3: Paper detail screen (external links, references/citations
      sections)
- [x] M4: Save/bookmark feature (SwiftData `SavedPaper`, Library tab),
      plus reading history and search history
- [x] M5: Explore tab — a browsable catalog, **no algorithm**: static
      shelves over dynamic queries, the way Music's Browse works. See
      [Explore](Docs/explore.md).
- [x] M6: New tab — **no algorithm either.** The axis is time: papers
      grouped by day, newest first, never ranked, filtered only by the
      reader's explicitly chosen category. See [New](Docs/new.md).
- [x] M7: Related — the ranking function itself (`Recommender.related`),
      now backing `PaperDetailView`'s Related carousel. Built general
      from the start: *given a set of papers, return ranked related
      ones.* See [Home, and the recommendation
      function](Docs/home-and-recommendation.md).
- [x] M8: Home tab — that same function over the library and history, as
      a fixed spine above a day-rotating, indefinitely-scrolling stream
      of shelves. No derived state is stored, so iCloud sync stays a
      matter of the three existing SwiftData models. See
      [Home](Docs/home-and-recommendation.md).
- [x] M9: Polish (dark mode, Dynamic Type, offline cache, TestFlight)

**The tab axes, which the milestones exist to keep apart:** Home is
*you*, New is *time*, Explore is *everything that isn't you*. Any
feature that blurs two of these belongs in neither.
