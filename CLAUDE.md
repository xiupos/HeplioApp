# Implementation Notes

Heplio for iOS and iPadOS: an unofficial client for [INSPIRE-HEP](https://inspirehep.net). What the code does not say by itself: the reasons behind decisions, pitfalls, and what only the iPad can check.

It is one of the Heplio apps, one for each platform. They share behaviour, not code or design. The behaviour is specified in `spec/SPEC.md` of the GNOME app, [heplio-gtk](https://github.com/xiupos/heplio-gtk) (checked out at `~/Projects/heplio-gtk`), whose `CLAUDE.md` also has the reasons that do not depend on the platform (INSPIRE's quirks, `fields=`, one request per page, PDFs and covers). `spec/cases.json` here is a copy of its test cases, so that the tests need nothing outside this project: copy it again when it changes there. A change of behaviour goes into that `SPEC.md` first, not here.

**Keep it small enough to read.** Five source files, no subfolders, no docs folder. A new feature goes into the file that has its kind. Do not bring back what the app had before it was rebuilt from the spec: recommendations (Home), New, Explore, a history of viewed papers, a cache of responses on disk, or TeX typeset in a web view per row.

## Environment

- Swift Playgrounds on an iPad; there is no Mac and no Xcode. The project is written on Linux and synced to the iPad with Syncthing.
- `Package.swift` is generated by Playgrounds: change it only as the app settings in Playgrounds would, except for `additionalInfoPlistContentFilePath: "Info.plist"`. One target, `AppModule`, with `path: "."`, so every `.swift` file in the project is compiled. No packages, no extensions.
- **`Info.plist`** holds only `ITSAppUsesNonExemptEncryption` = `false`, so that App Store Connect does not ask about encryption for each build: the app uses only the system's HTTPS, which is exempt. Playgrounds has no supported way to add keys; `additionalInfoPlistContentFilePath` merges this file into the app's, as in PDFViewerApp (`~/Syncthing/swift-playgrounds-project/PDFViewerApp.swiftpm`, whose CLAUDE.md checked it on the iPad). Playgrounds may drop the line when it writes `Package.swift` again: check it is still there before uploading a build. Nothing in the app depends on it.
- Fixed: bundle ID `net.xiupos.heplio`, the team ID, the AppIcon in `Assets.xcassets`, the orange accent colour, iOS 26, Swift 5 language mode. UI text is in English.
- Syncthing may leave `*.sync-conflict-*` copies of files. In `Sources/` they cause "invalid redeclaration" errors: delete them first.

## Testing

`Core.swift` builds on Linux (Swift 6.4 here). Its tests, at the end of the file under `#if os(Linux)`, run every section of `cases.json` as the spec says (`spec_cases` in heplio-gtk's `src/core.rs` is the model, `loosen` included), and a few more: plain text, JSON files, refdir rules the cases do not reach (from `refdir/tests/rules.rs`), suggestions.

```bash
swiftc -parse-as-library Sources/Core.swift -o /tmp/heplio-spec && /tmp/heplio-spec
```

They find `spec/cases.json` from the source file's path, so they run from any folder. Give another path as an argument, such as heplio-gtk's own copy, to check that this one is current. Nothing in `Core.swift` uses the network: `URLSession` is in `Lists.swift`, which needs the iPad, as everything that imports SwiftUI does. `swiftc -frontend -parse` checks the other files' syntax here, and no more.

## Core

- **JSON is Foundation's**: `JSON` is decoded by `JSONDecoder` and written by `JSONEncoder` (sorted keys, indented). Objects are dictionaries, so files are compared as values, never as text, as the spec says. A whole number is `int` (`JSONDecoder` reads `1.0` as an `Int`), and `==` compares numbers by value.
- **Except the order of `sources`.** refdir layers the resolved item by `sources.*.csl` in the order of the keys in the file (`schema/v1.json`); `JSONDecoder` does not keep it. `sourceOrder` reads only that order from the bytes, and `RefdirEntry.layers` uses it; keys it misses come after, by name. Writing does not keep it: `JSONEncoder` sorts the keys, so an entry Heplio rewrites has its sources in name order, which changes the resolved item only where two sources' CSL have the same field. The fixture with `ads` and `inspire` passes either way.
- **refdir** is written here from the `refdir` crate (`~/Projects/refdir/refdir/src/lib.rs`, `tags.rs`), whose code and tests are the rule: entries, the resolved item, the main file, name order (`namePrecedes`), free folder names, taken keys, pruning, `writeAtomic`, and editing tags (read again just before writing, never written over when not all strings, repeats removed). A rule refdir changes is changed there first, then here.
- **Plain text** (`plain`, `TeX`) is a small converter of its own: HTML first (`<sup>`, `<sub>`, `<inf>` become scripts, other tags go, then entities), then the `$` that are pairs, then TeX: commands to symbols, scripts to Unicode where every character has one (else `^x`, `_(xy)`), accents to combining marks, the arguments of font commands kept, unknown commands dropped. Spaces in math are dropped, as TeX drops them (`$H \to \gamma\gamma$` → `H→γγ`). Upright letters, not math italics. It is fast enough to make every row's title and abstract line when a page of a list is parsed, off the main thread (`ListRow`).
- **Names that shadow.** A method or property hides a global function of the same base name inside its type, so the Core's functions and `Library`'s methods have different names (`savePaper` and `save`, `addTag` and `attach`, `readLibrary` and `papers`). Keep them apart.
- `timestamp()` is here, in UTC, so that the tests can check it.

## UI

- **An iOS app.** The spec decides what the app does; how it looks is the platform's. Native SwiftUI only: no custom chrome. heplio-gtk's UI decisions answer GTK's problems (rebuilt rows losing clicks, toasts, a boxed list for everything): take its reasons only where they hold on iOS, and otherwise do what SwiftUI does most simply. The models are App Store (a paper's page), Books (the Library's cards), Music and Files, and illust-shelf-ios, whose answers to the same questions (tabs, search fields, navigation, input methods) are kept unless there is a reason.
- **Tabs.** Library, Search, and INSPIRE, as the spec has them. Library and Search are illust-shelf-ios's: Library shows every saved paper and is never searched, so that it keeps its place; Search finds among them, and lists the tags while its field is empty. All three are ordinary tabs, named on every device: no `role: .search`, which on an iPhone turns the bottom tab bar into the field, and on an iPad leaves only a magnifying glass at the end of the tab bar. INSPIRE is a globe. Search fields are under the navigation bar (`.navigationBarDrawer(displayMode: .always)`). A tab's first page has a large title in the row of its buttons (`.inlineLarge`), which an iPad leaves out beside a tab bar at the top.
- **Navigation.** Each tab is a `Stack`. Pages are `Route` values, pushed by `NavigationLink(value:)`; `Destination` turns them into views.
- **The library** is read off the main thread (`Library.reload`, or `refresh` without waiting): `queries.json` and every `entry.json`. A read overtaken by a newer one is dropped. It runs when the folder is opened, after every change, on pull to refresh and Reload in Settings, and when the app becomes active (`scenePhase`), so that a synced change shows when the user comes back. Changes themselves are written on the main thread, then read back. Paper pages read their entry from `Library` (`paper(_:)`): by recid, the first by folder name.
- **The folder** is chosen with `fileImporter` and kept as a security-scoped bookmark, as in illust-shelf-ios. Nothing stores its path, which changes on iOS. A file iCloud Drive has evicted is a hidden `.<name>.icloud`; `downloadEvicted` asks for `entry.json`s that are, so that a later reload lists them.
- **One request per page.** A list loads its first page when it first appears and when the sort changes, not when it comes back into view; the next page when its last row appears. It holds the page loading as a `Task`, which a change of sort cancels. A paper page loads once, then its figures one after another; one not loaded when the page goes is loaded when it comes back. `Net` has two ephemeral sessions without a cache: INSPIRE's with 30 seconds, arXiv's with 5 minutes for PDFs.
- **INSPIRE's search** runs on Return only (`onSubmit(of: .search)`). While the field is empty, the page lists the saved queries and the recent searches (examples while there are none); a search's list takes their place until the field is emptied. Recent searches are rows of the page, not the field's `searchSuggestions`: a suggestion cannot be swiped away, and the spec lets the user remove one. Tapping one searches it again. The Search Tips link is in the toolbar.
- **Saved queries** are reordered in edit mode (Edit, in their section's header: in the toolbar, an iPad folds it into a ⋯ menu beside the tab bar), renamed in an alert, and removed by swiping or from the context menu, without asking, as list rows are on iOS: a query is easily saved again. Each action checks that the query at its index on disk is still the one shown (`changeQuery`), since another device may have changed the file.
- **Saving a query** names it by the list's title: the search text, the author's short name, or "References of J.M. Maldacena (1997)".
- **The paper page** is a `ScrollView` of `Shelf`s, as the App Store's: the hero (cover, title, three authors, date and journal, one main button: Read, Get PDF, or Read on arXiv), tiles, the abstract (6 lines, with More only when it is cut, measured with `onGeometryChange`), the tags of a saved paper, the figures, three authors and Show All (a page of them all), and the links. The star saves; for a saved paper it removes, after asking. The share menu shares the PDF in the library (a file, to open in another app: iOS has no default app for PDFs), the arXiv link, or the INSPIRE link. Its items are buttons that open `ShareSheet` (a `UIActivityViewController`) in a sheet from the page: a `ShareLink` inside a toolbar menu opened its sheet squeezed into the navigation bar. The ⋯ menu copies BibTeX, the arXiv ID, and the citation key (the texkey), and removes the PDF or the paper. The main button shows Read for any PDF in the entry, also of a paper not on arXiv.
- **PDFs** are downloaded only when the user asks (Get PDF), into the entry, saving the paper first; they open with Quick Look (`.quickLookPreview`). Removing the paper or Heplio's PDF deletes it after asking: iOS has no trash for the user's folders.
- **Covers** have a hairline border, so that a white page shows on a white background. They are rendered with PDFKit by the `Covers` actor, one at a time, with `PDFPage.thumbnail(of:for:)`, which turns the page by its rotation and keeps its crop box's origin: drawing the page into a context by hand put rotated (landscape) and offset pages in the wrong place. 200 points wide, to `Caches/covers/2/<SHA-1 of the PDF's path>.png`, and again when older than the PDF. The card shows the cover filling its frame, centred (`scaledToFill`). Since the folder's path can change, old covers may stay in the caches until iOS clears them.
- **Figures** are drawn over white (`onWhite`), since some are transparent, and open in the browser.
- **Tags.** While Search's field is empty, the library's tags are a `List` with a section for each namespace (capitalized, Other Tags last), each row the tag's value and count, as heplio-gtk has them: rows show any number of tags, where a row of buttons hides most of them. With text, the tags that match are bordered capsule links (`TagLinks`) above the cards. A paper's page shows its tags the same way, with Edit, which opens `TagEditor`, a `Form` in a sheet, where tags are removed by swiping, as in illust-shelf-ios's Info. Suggestions there are rows to tap, never a completion that changes the field's text: an input method's unfinished text would be lost. The field is emptied only after a tag is added.
- **Errors** of the folder are shown in an alert (`Library.error`), by kind (`message`); a list or page that fails to load says why, with Try Again, and tells a 429 apart.
