# Implementation Notes

Heplio for iOS and iPadOS: an unofficial client for [INSPIRE-HEP](https://inspirehep.net). What the code does not say by itself: the reasons behind decisions, pitfalls, and what only the iPad can check.

It is one of the Heplio apps, one for each platform. They share behaviour, not code or design. The behaviour is specified in `spec/SPEC.md` of the GNOME app, [heplio-gtk](https://github.com/xiupos/heplio-gtk) (checked out at `~/Projects/heplio-gtk`), whose `CLAUDE.md` also has the reasons that do not depend on the platform (INSPIRE's quirks, `fields=`, one request per page, PDFs and covers). `spec/cases.json` here is a copy of its test cases: copy it again when it changes there. A change of behaviour goes into that `SPEC.md` first.

**Keep it small enough to read.** Five source files, no subfolders, no docs folder. No recommendations, history of viewed papers, "New", "Explore", cache of responses on disk, or TeX typeset in a web view.

## Environment

- Swift Playgrounds on an iPad; there is no Mac and no Xcode. The project is written on Linux and synced to the iPad with Syncthing.
- `Package.swift` is generated by Playgrounds: change it only as its app settings would, except for `additionalInfoPlistContentFilePath: "Info.plist"`. One target, `AppModule`, with `path: "."`, so every `.swift` file in the project is compiled. No packages, no extensions.
- `Info.plist` holds only `ITSAppUsesNonExemptEncryption` = `false`: the app uses only the system's HTTPS, which is exempt, so App Store Connect need not ask for each build. Playgrounds has no supported way to add keys; that line of `Package.swift` merges the file, as in PDFViewerApp (`~/Syncthing/swift-playgrounds-project/PDFViewerApp.swiftpm`). Playgrounds may drop the line when it writes `Package.swift`: check it before uploading a build.
- Fixed: bundle ID `net.xiupos.heplio`, the team ID, the AppIcon in `Assets.xcassets`, the orange accent colour, iOS 26, Swift 5 language mode. UI text is in English.
- Syncthing may leave `*.sync-conflict-*` copies of files. In `Sources/` they cause "invalid redeclaration" errors: delete them first. A conflict can also put back an older copy of a file: check the diff after one.

## Testing

`Core.swift` builds on Linux (Swift 6.4 here). Its tests, at the end of the file under `#if os(Linux)`, run every section of `cases.json` as the spec says (`spec_cases` in heplio-gtk's `src/core.rs` is the model, `loosen` included), and a few more: plain text, JSON files, refdir rules the cases do not reach (from `refdir/tests/rules.rs`), suggestions.

```bash
swiftc -parse-as-library Sources/Core.swift -o /tmp/heplio-spec && /tmp/heplio-spec
```

They find `spec/cases.json` from the source file's path; give another path as an argument, such as heplio-gtk's copy, to check that this one is current. `URLSession` is in `Lists.swift`, so nothing in `Core.swift` uses the network. Everything that imports SwiftUI needs the iPad; `swiftc -frontend -parse` checks its syntax here, and no more.

## Core

- **JSON is Foundation's**: `JSONDecoder` and `JSONEncoder` (sorted keys, indented). Files are compared as values, never as text. A whole number is `int` (`JSONDecoder` reads `1.0` as an `Int`), and `==` compares numbers by value.
- **Except the order of `sources`.** refdir layers the resolved item by `sources.*.csl` in the order of the keys in the file, which `JSONDecoder` does not keep: `sourceOrder` reads only that order from the bytes. Writing sorts the keys, so a rewritten entry has its sources in name order; that changes the resolved item only where two sources' CSL have the same field.
- **refdir** is written here from the `refdir` crate (`~/Projects/refdir/refdir/src/lib.rs`, `tags.rs`), whose code and tests are the rule. A rule refdir changes is changed there first, then here.
- **Plain text** (`plain`, `TeX`) is a small converter of its own: HTML first (`<sup>`, `<sub>`, `<inf>` become scripts, other tags go, then entities), then the `$` that are pairs, then TeX: commands to symbols, scripts to Unicode where every character has one (else `^x`, `_(xy)`), accents to combining marks, fonts' arguments kept, unknown commands dropped. Spaces in math are dropped, as TeX drops them (`$H \to \gamma\gamma$` → `H→γγ`). Upright letters. A list's rows are made when its page is parsed, off the main thread (`ListRow`).
- **Names that shadow.** A method hides a global function of the same base name inside its type, so the Core's functions and `Library`'s methods have different names (`savePaper` and `save`, `addTag` and `attach`, `readLibrary` and `papers`).

## UI

- **An iOS app.** The spec decides what the app does; how it looks is the platform's. Native SwiftUI only, done the simplest way SwiftUI has: heplio-gtk's UI decisions answer GTK's problems, and hold here only where the reason does. The models are App Store (a paper's page), Books (the cards), Music (the Search tab), and illust-shelf-ios (tabs, search fields, navigation, input methods).
- **Tabs.** Library shows every saved paper and is never searched, so that it keeps its place. Search has one field and a segmented toggle of its scope, INSPIRE or Library, under it and always shown (`safeAreaInset`), kept in `@AppStorage("scope")`. `searchScopes` shows no bar with a field that is always shown, and a toggle beside the field in the navigation bar (`placement: .toolbar`) breaks the iPad's layout. Search is a search tab (`role: .search`) only where the tab bar is at the top: at the bottom it would turn the tab bar into its field. Search fields are under the navigation bar (`.navigationBarDrawer(displayMode: .always)`).
- **Navigation.** Each tab is a `Stack`; pages are `Route` values, pushed by `NavigationLink(value:)`.
- **The library** is read off the main thread (`Library.reload`, or `refresh` without waiting); a read overtaken by a newer one is dropped. It is read when the folder is opened, after every change, on pull to refresh and Reload, and when the app becomes active (`scenePhase`), so that a synced change shows. A paper page finds its entry by recid, the first by folder name (`paper(_:)`).
- **The folder** is chosen with `fileImporter` and kept as a security-scoped bookmark. Nothing stores its path, which changes on iOS. iCloud Drive leaves a file not on the device as a hidden `.<name>.icloud`: `downloadEvicted` asks for such `entry.json`s.
- **One request per page.** A list loads its first page when it first appears and when the sort changes, not when it comes back into view, and the next when its last row appears; it holds the page loading as a `Task`, which a change of sort cancels. A paper page loads once, then its figures one after another. `Net` has two ephemeral sessions without a cache: INSPIRE's with 30 seconds, arXiv's with 5 minutes.
- **Searching INSPIRE** runs on Return only, the library as the user types. Changing to INSPIRE with text searches it once. While the field is empty, INSPIRE lists the saved queries and the recent searches, or examples (`InspireHome`). Recent searches are rows, not `searchSuggestions`, which cannot be swiped away. Search Tips is in the toolbar.
- **A list's sort and Save Query** are on the row of its count, on every list once there are results, not in the toolbar, where the tab's own buttons are.
- **Saved queries** are reordered with Edit, in their section's header (in the toolbar, an iPad folds it into a ⋯ menu), renamed in an alert, and removed without asking. Each action first checks that the query at its index on disk is still the one shown (`changeQuery`). A saved query is named by its list's title: the search text, the author's short name, or "References of J.M. Maldacena (1997)".
- **The paper page** is an inset-grouped `List`, so that its tags, authors, and links are standard rows: the hero (cover, title, three authors, date and journal, one main button: Read, Get PDF, or Read on arXiv) on a clear row, tiles, the abstract (6 lines, with More only when cut, measured with `onGeometryChange`), figures, tags, three authors and Show All, links. The tiles are buttons that push with `navigationDestination(item:)`: links in a row that holds several share the row's tap. A `List` cannot sit inside a `ScrollView`, so the page is all `List`. The star saves, or removes after asking. The share menu's items are buttons that open `ShareSheet` from the page: a `ShareLink` in a toolbar menu squeezes its sheet into the navigation bar. Sharing the PDF is how it opens in another app: iOS has no default app for PDFs.
- **PDFs** are downloaded only when asked (Get PDF), into the entry, saving the paper first. They open with Quick Look (`PDFReader`, a `QLPreviewController` presented from UIKit, since `quickLookPreview` cannot allow editing), which saves markup into the file itself (`.updateContents`); the library is then read again, so the cover follows. Get PDF is not offered while Heplio's PDF is there behind another file. Removing the paper or Heplio's PDF deletes it after asking: iOS has no trash for the user's folders.
- **Covers** are rendered by the `Covers` actor with `PDFPage.thumbnail(of:for:)`, which turns a rotated page and keeps the crop box's origin (drawing a page into a context by hand gets both wrong), 200 points wide, to `Caches/covers/<version>/<SHA-1 of the PDF's path>.png`, and again when older than the PDF. They fill the card from its centre (`scaledToFill`), with a hairline border, so that a white page shows on white.
- **Figures** are drawn over white (`onWhite`), since some are transparent, and open in the browser.
- **Tags.** With the field empty, Library's scope lists the tags in a `List`, a section for each namespace (capitalized, Other Tags last), as heplio-gtk has them; with text, the tags that match are capsule links (`TagLinks`) above the cards. A paper's tags are a section of its page, as illust-shelf-ios's Info has them (`PaperTags`): the value with the namespace after it, opening the tag's page, removed by swiping or from the row's menu (which also copies); under them, a field that adds a tag on Return, and suggestions. Suggestions are rows to tap, never a completion that changes the field's text, which would lose an input method's unfinished text; the field is emptied only after a tag is added.
- **Errors** of the folder are shown in an alert (`showsErrors`, on the root and on each sheet); a list or page that fails to load says why, with Try Again, and tells a 429 apart.
